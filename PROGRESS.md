# PROGRESS — конструктор маршрутов метро СПб

Статус проекта: что сделано и что в планах. Обновляется по ходу работы.
Структуру файлов и логику данных/движка см. в PROJECT_MAP.md — сюда её не дублируем.

## Сделано

### Данные
- 8 станций Московско-Петроградской линии переведены из docx в JSON (`data/stations/*.json`) + `data/lines.json`
- Формат шагов: массив `{text}` / `{when, text}` — условные шаги (пока только `arrival_from`) отмечены явно, задел под пересадки и нетиповые выходы
- Все станции сверены построчно с исходным docx-документом (канонический источник), расхождения исправлены:
  - Пионерская, Проспект Просвещения — были перепутаны направления поворота на выходе
  - Проспект Просвещения — лишний шаг входа "Поверните направо, идите прямо по коридору" убран (ошибка в самом docx)
  - Проспект Просвещения — `exit.steps` дополнительно исправлены ещё раз по личной проверке на месте (не по docx): arrival_from Купчино → «Поверните направо», arrival_from Парнас → «Поверните налево» (было наоборот)
- Проверена гипотеза «поворот на выходе = сторона platform.directions (или противоположная)» на всех станциях с данными — **не подтвердилась**: Озерки следуют правилу «та же сторона», а Петроградская/Горьковская/Пионерская/Просвещение — правилу «противоположная сторона». Вывод закреплён в PROJECT_MAP.md: поворот на выходе — независимый факт по каждой станции, доверять можно только docx или личной проверке на месте, не формуле
- Удельная — помечена `status: "no_data"`, корректно обрабатывается (в списке есть, но выбрать нельзя)

### Движок и интерфейс
- `js/data-loader.js` — загрузка данных через `fetch` (нужен локальный сервер, `file://` не работает из-за CORS)
- `js/route-builder.js` — определение направления и `arrival_from` без хардкода названий станций (через терминал линии + `order`), сборка секций маршрута
- `js/app.js` + `index.html` + `css/style.css` — форма выбора станций, кнопка ⇄ («поменять местами»), вывод результата без перезагрузки страницы

### Выбор станции — текстовое поле-фильтр + нативный `<select>`
- `js/combobox.js` прошёл три версии: ARIA `role="combobox"`/`role="listbox"` → список кнопок под полем → текущая, третья версия
- Первая версия (ARIA combobox) оказалась ненадёжной на сенсорных читалках: свайпы и touch-исследование вокруг поля закрывали список, VoiceOver/TalkBack не всегда «видели» его
- Вторая версия (кнопки) была надёжной, но растягивала страницу списком кнопок и требовала отдельного `aria-live`-счётчика найденных станций — из-за него при программной смене станции (кнопка «⇄») озвучивалось сразу три сообщения подряд (счётчик поля «откуда», счётчик поля «куда», и само подтверждение свапа)
- Третья версия: обычный текстовый `<input>` (фильтр по подстроке) + обычный нативный `<select>`, который показывает либо отфильтрованный, либо (если поле пустое) полный список станций. Открытие/закрытие списка, объявление количества и текущей позиции варианта — встроенное поведение браузера и ОС, а не самодельный ARIA-паттерн. Выбор не подставляется молча: если станция, выбранная раньше, выпала из-под фильтра, `<select>` показывает недоступный для выбора плейсхолдер, а не первый попавшийся вариант
- Отдельный `aria-live`-счётчик найденных станций убран за ненадобностью — заодно устранена и тройная озвучка при свапе, описанная выше
- Список станций у отдельного поля больше не занимает произвольную высоту в потоке страницы — это встроенное поведение `<select>`, а не то, что растёт вместе с базой станций

### Инструкция и «О нас»
- `instructions.html` заполнена: как пользоваться формой, инструкция по устройствам (Windows/NVDA, Android/TalkBack, iPhone/VoiceOver), правило постоянных ориентиров
- Раскрывающиеся блоки по устройствам — `js/instructions.js`, паттерн ARIA disclosure (кнопка с `aria-expanded` + `aria-controls`, панель скрыта `hidden`). Отдельной кнопки «Свернуть» внутри панели больше нет — кнопка устройства сама работает как тумблер (открыть/закрыть); отдельная кнопка была лишней и с ней NVDA иногда терял фокус, если она была найдена стрелками, а не табом
- `about.html` — страница «О нас» с описанием проекта и контактами автора (наполнена пользователем)
- Общее меню сайта вынесено в `js/nav.js`: генерируется один раз и подставляется на всех трёх страницах через `<div id="site-nav"></div>`; ссылка на текущую страницу помечается `aria-current="page"`

### Доступность (проверено с NVDA, VoiceOver, TalkBack)
- Блок результата — НЕ `aria-live`, чтобы весь маршрут не зачитывался разом при нажатии кнопки; озвучивается только короткое подтверждение через `#status`
- На загрузке страницы — без служебных объявлений
- Вывод структурирован: `h2` (маршрут + число шагов) → `h3`-секции (Вход А / На платформе А / Выход Б) → обычные абзацы, без `<ol>`/`<li>`
- Секция «На платформе Б» скрыта в выводе, пока нет пересадок (данные всё равно считаются в движке — понадобятся позже)
- Сторона посадки на платформе А — фраза «Поезда в направлении Х отправляются слева/справа»
- Первый (условный) шаг выхода — с приставкой «После выхода из поезда...»
- Исправлен баг: `#status` не озвучивал повторно одинаковый текст (например «Маршрут построен.» дважды подряд) — NVDA не видит изменения в дереве доступности, если текст не поменялся. Теперь текст сначала очищается, и только следующим тиком ставится новый — так гарантируется реальное изменение при каждом вызове
- Исправлен баг: при загрузке страницы фокус неожиданно уезжал в поле «Станция назначения» — программная установка станций по умолчанию по ошибке тоже вызывала `focus()`, предназначенный только для клика мышью
- Исправлен баг: если кнопку «Свернуть»/переключатель устройства в инструкции активировать стрелками в режиме чтения NVDA (а не табом), фокус после действия улетал в конец страницы — известная гонка между Browse Mode и Focus Mode NVDA; решено переносом `focus()` на следующий тик через `setTimeout(..., 0)`

3. ~~Станции с двумя выходами (Проспект Славы и подобные)~~ — сделано: у станции теперь список `vestibules` (вестибюлей), каждый со своими шагами входа и выхода; при нескольких вестибюлях в форме появляется дополнительное поле выбора («вход»/«выход»), без выбора по умолчанию.
